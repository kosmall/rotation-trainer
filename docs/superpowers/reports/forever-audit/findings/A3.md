# A3: talents (audit findings)

Auditor A3. Scope: `src/forever/data/talents.json`, `src/forever/talents.ts`, `src/forever/effects.ts`,
`src/forever/builds.ts`, and the places in `src/forever/fight.ts` (plus `stats.ts`, `runner.ts`, `rotations.ts`
where they read a talent) that apply talent effects. No repository file other than this one was changed.
Reproduction scripts live in the scratchpad `/tmp/claude-0/-home-user-rotation-trainer/05276e97-9c03-5b59-93ad-fdb2660cdf40/scratchpad/`
(`a3_*.ts`, patched copies in `patched/`); run with `npx tsx <script>` from the repo root.

Sources used: `docs/forever-data-ledger.md` (sections 1, 2, 3, 4, 7), the `source` field of each talent in
`talents.json` (guildorder / allthings / timesaver / Wowhead Forever quotes). Important: `src/data/classes/warlock/talentDescriptions.json`
is **Wowhead TBC** text (its own header says so; it feeds the TBC trainer, not Forever), so it is not a source of truth for
Forever values. Where it differs from the Forever data this is listed under "Compared with talentDescriptions.json" at the end; none of
those differences is by itself a finding.

Note for the orchestrator: the task text said "24 modelled, 40 unmodelled". The data has **52 talents: 35 `modelled`, 17 `unmodelled`**
(tree sizes 17/19/16 as the ledger says; `a3_orders.ts`: `talents 52 modelled 35 unmodelled 17`). The 17 unmodelled: grim_reach, amplify_curse,
curse_of_exhaustion, master_summoner, decimation, fel_domination, improved_felhunter, destructive_reach, molten_skin, shadowburn, intensity,
conflagrate, pyroclasm, bane_of_havoc, fire_and_brimstone, shadow_and_flame, incinerate.

## Uwagi spoza zakresu

1. `src/forever/web/addon-import.ts:28-29`: the digit string of the addon export is mapped by index onto `TALENTS` in file order, and the picks are emitted in that tree order. The order of `talents.json` is therefore load-bearing for the import (it is sorted by tree, row, col; no test pins it to the addon's order), and a character with 51 points imported then run at a lower level plays only the first `pointsAtLevel` picks of that tree order (all Affliction first), not the order the player spent points. A5.
2. `params.json` `fsr_regen_fraction` 0 and `cast_floor_ms` 500 (both `verify`) change how Soul Harvest and a partial Improved Corruption behave; A2.
3. `runner.ts:146` and fight.ts:789: "An Imp has no mana regeneration" is an assumption with no ledger entry; with it the Imp's Firebolt stops after about 3 pulls (see A3-001 reproduction). Needs an A4 decision (ledger section 4 item 2).
4. `fight.ts:716`/`721`: percentage damage reductions and armor combine additively on the pet and not at all for the warlock's own `playerArmor` formula; A4.
5. The plan `docs/superpowers/plans/2026-11-25-wow-forever-leveling.md` lines 78 and 81 (default `pre_respec_build = AFF_WRACK`, `DEMO_CORE`, seven variants) is outdated against the code (22+ variants, no respec); documentation only.
6. `report.ts:90` text says the Demonology builds are "DEMO_PACT_R1 = Bane 2/5 + Shadow Bolt rank 1" but `builds.json` DEMO_PACT_BANE2 takes Suppression 4 in its last points and Improved Shadow Bolt only after Improved Corruption 5 and Soul Harvest 2 (ISB 1/5 at level 50, 5/5 at 59, a3_orders.ts); not an error, but a build-design fact worth knowing when reading level-50 results.
