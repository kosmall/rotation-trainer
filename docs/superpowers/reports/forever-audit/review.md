For discover it is wrong: stage seeds are `seed*1e6+offset` and each session seed is multiplied by 100003 in `pullSeed`, so from about `seed >= 9e4` the new hash branch in `pullSeed` is taken (the old code rounded and collapsed neighbouring pulls there). ## (f) Logic errors introduced by the fixes

Read in full: the diffs of `fight.ts`, `runner.ts`, `rotation-genes.ts`, `stats.ts`, `builds.ts`, `rotation-spec.ts`, `ltpolicy.ts`, `discover/engine.ts`, `web/api.ts`, `web/custom.ts`, `SettingsBar.tsx` and the UI display diffs.

**No `block` item.** The Life Tap, Demonic Energies and Demonic Sacrifice changes in `runner.ts` were traced step by step:
- Soul Harvest carry (`runner.ts:152, 250, 302-305`): `gapMs = totalSec - lastPullEndSec` is measured after taps, funnel and break, so it contains the death penalty, resummon, the walk (added at the end of the previous iteration) and the paid tap time, each once. `lastPullEndSec` is set right after `pullSec` is added, so no second is counted twice and none is missed (no off-by-one). The walk's own regeneration sees the buff reduced by the death penalty and the resummon that come before the walk (right order: death, resummon, transition).
- Time accounting of Life Tap between pulls (`:186-207`): paid time is the overflow of the cumulative tap time over `transition_sec`, computed as a difference, so both passes together are paid exactly as one pass would be. The time goes to `restSec` and `totalSec`, the `lifeTapSec` counter always gets the whole tap time. No double counting with the in-fight `lifeTapCount * gcd`, which only counts in-fight taps.
- Demonic Sacrifice (`:173-184`): the demon state is built exactly as in `fight.ts:174-179` (`demonsAt` with the same mob count, sacrifice only with the talent, Pact keeps it only for a different summoned demon), the per-second rates equal `fight.ts:798-799`. The regeneration is added to the walk, the break, the paid tap time and the funnel; in the fight it is added to `combatRegenPerSec` in the same additive way, so nothing is applied twice. One approximation, `note`: the break length from `planRest` is not shortened by the sacrifice regeneration, so a Voidwalker-sacrifice build drinks a bit more than needed and is slightly under-estimated (conservative).
- Demonic Energies between pulls (`:195`): only for a living demon (`petMana` undefined = full or no demon), capped by `grantDemonicEnergiesMana`, same helper as the fight. Correct.

Small findings:

1. `note` `src/forever/rotation-genes.ts:131-139` (A5-005). The parameter overrides are folded into the genes as the commit describes. Two consequences to know, both by design but worth a line in the report: (i) `aff_use_immolate` / `demo_use_agony` force the effect on for every genes build, so a discovery run with such an override contains combos whose label (`rotationLabel`, report text) says "no Immolate" but that play it; (ii) a `corruption_min_ttk_sec` different from 6 replaces the gene floor of every effect, which collapses the `minTtkSec` 0/6/12 search dimension of discover, and an override equal to the default (6) is indistinguishable from "no override" (so `--param corruption_min_ttk_sec=6` cannot force 6 on a genes build with floor 12). The no-override path is proven identical (above).
2. `note` `src/forever/fight.ts:839` and `:890-891` (A4-001). The Torment fix interacts with a fight constant that is not a parameter: a demon other than the Imp regenerates a hard-coded 0.5 mana/s in combat (`pet.mana + 0.5 * dt`), while Torment now drains 20 mana per 5 s (4/s). The size of the Voidwalker loss (the commit measured about -10% for 2 mobs) therefore depends on `pet_ooc_mana_per_sec` (0.5, `verify: true`) and on that constant. This is already acknowledged in the commit; it should be on the owner list.
3. `note` `src/forever/stats.ts:45-51, 178` (A2-017). `statLevel` now throws for a level below 1 or non-finite where it used to clamp silently (any bad caller now crashes instead of reading the level 10 row). `armorReduction` (`:178`), `demonArmorOf` and the pet rank lookups still use the raw level, so the commit statement "everything that grows with the level uses the same table level" is not complete for levels above 60; the UI and the API cannot reach those levels (10-59), so no observable effect.
4. `note` `src/forever/web/api.ts:77` (A5-006). Settings seeds are now clamped to 0..2^31-1 in the web settings; a negative seed that used to be accepted becomes 0 (a different stream), and the seed input (still a plain number field) clamps while typing. Only the web path; saved settings with a negative seed change their result silently.
5. `note` `src/forever/builds.ts:257`. `pre in RAW.orders` accepts inherited property names such as `"constructor"` as a valid `pre_respec_build`; use `Object.hasOwn`. Cosmetic (the option does nothing for shipped builds, see A3-017).
6. `note` `src/forever/report.ts` `formatRunHeader`: "Spellstone: yes" is inferred from `haste_pct > 0 || shadow_spell_power_bonus > 0`, so a plain `--param haste_pct=2` prints it as a Spellstone. Display only.
